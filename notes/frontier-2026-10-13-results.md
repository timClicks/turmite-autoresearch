### A3: why the ant's visit density equals the rotor's cone (analytic, 2026-10-13; no new simulation)
The frontier note proposed a numerical free-boundary solve. It is not needed: the profile follows from one integral.
Assume (a) occupancy inside the territory at time t' is uniform, n(r,t') = 1/A(t') for r < R(t') (the well-mixed property; kappa ~ 1) and (b) A(t) = A_t (t/t_end)^a. A cell at radius r is inside from t_r (defined by R(t_r) = r, i.e. t_r/t = (r/R)^(2/a)). Its accumulated visits are
rho(r) = integral from t_r to t of dt'/A(t') = (t / ((1-a) A)) * (1 - (r/R)^(2(1-a)/a)).
For a = 2/3 this is exactly (3t/A)(1 - r/R): the cone with the measured prefactor, and it integrates to t over the disc (pi R^2 / 3 * 3t/A = t), as required. So the cone is the footprint of a uniformly mixing walker inside a disc growing as t^(2/3); nothing about rotors or ants enters beyond (a) and (b). This also explains why ant and rotor agree even though their kappa differ (0.9 vs 2.0): kappa only changes a thin edge layer, not the bulk integral.
Prediction from the formula that the earlier data can be checked against: for the measured finite-window rotor exponent a = 0.687 the prefactor is 1/(1-a) = 3.19 and the profile exponent is 0.91, versus the measured centre value 2.87 (`experiments/archive/2026-10-shape-limit/results/shape_stats.txt`, shells of 0.075 R_eq, mean over 40 runs) and an almost straight profile. The centre is 10% below 3.19 and 4% below 3.0, so the finite-a formula is not a better fit than a = 2/3; the shell-averaging (0.075 R_eq) lowers the centre value by ~ 3-4% for a linear cone, which accounts for most of it. Not resolved at better than ~5%.
Controls (not run): the formula gives, for a = 0.94 (random-background radius exponent 0.47, item 26), a flat-topped profile 1 - (r/R)^0.13 with prefactor 16.7 t/A; for a = 1 (the sqrt(t) turmite cluster) a logarithmic profile (t/A) ln(R^2/r^2). These are sharp predictions that would break the idea if measured otherwise; they need profile output from the `ext` binary (not done).
Status: derivation done (conditional on uniform occupancy and the exponent); the controls are NOT run. Revised understanding: "cone" is not independent evidence for the cube root, it is implied by it plus uniform mixing, so A3 reduces to A1/C1 (why kappa ~ 1) and the 2/3 exponent itself.

### C1: heuristic for the cube root (2026-10-13; no new simulation)
dA/dt = c kappa P / A (identity). If P = p A^beta with beta = 1/2 and c kappa = const, then A^(1/2) dA = c kappa p dt, so A ~ t^(2/3). The exponent 2/3 therefore needs exactly two inputs: a compact, non-fractal boundary (P ~ R; supported by roundness, anisotropy 0.07 at 2^28, but beta fitted 0.52) and a time-independent product c * kappa. The mechanism for "c * kappa constant" is local (edge colour mix sets c; well-mixed occupancy sets kappa ~ O(1)), but no argument fixes kappa's value (0.9 for ants, 2.0 for the rotor), and a derivation of kappa = f(q) is not available. What does the heuristic predict that can fail: (i) the area exponent should equal (1 + g_c + g_k)/(2 - beta) per rule (this is the `a_pred` column of `probe_summary.csv`, tested already as a consistency check); (ii) a non-round limit shape with P ~ A^beta, beta != 1/2 would shift the exponent to 1/(2-beta); the hex/triangular and 3D variants do shift as expected for d = 3 (d/(d+1)), which supports the structure. Status: written heuristic; kappa = f(q) NOT derived (see A1).

### A1d: is kappa explained by a persistent random walk reflecting at a growing front? (hypothesis written 2026-10-13, before any run)

### E1 design: an excited random walk with a board (new walker; does stochastic memory reproduce the cube root or kappa?)
Walker `ew:P:SEED` ("once-excited"): each cell has a state 0/1/2 = visits so far capped at 2. On a visit to a state-0 cell the walker takes its first-visit step with a bias, then the cell moves to state 1: the heading is turned right with probability P_first (and the cell is marked); on state >= 1 cells the heading is turned right or left with probability 1/2 (memoryless). This is a cookie random walk: memory only in the first visit. Two controls in the same code: P_first = 0.5 (pure random walk) and a "rotor-on-first-visit" ablation is not run.
Honest status: this is a weak candidate; a one-visit cookie leaves little memory. The sharper board-memory walker is the **true self-avoiding walk**: at each step the walker picks among the 4 neighbours (not the one it came from? no: all 3 non-reversing moves) with probability proportional to exp(-g * visits(neighbour)), g = 0.5, 1, 2. Walker `tsaw:G:SEED`. This needs the board's visit counts, which the Walker trait does not give; implement as a stand-alone simulation in `examples/tsaw.rs` writing the same shape/probe rows (A, perimeter, kappa via a per-step edge flag) at checkpoints.
Predictions (fixed now): (E1a) TSAW area exponent for g in {0.5, 1, 2} is in [0.6, 0.75] for at least one g (a cube-root-like regime exists for a stochastic memory walker), reported with the local exponent at k = 20..26. (E1b) If it exists, its kappa at that g is rule-free: the between-seed ICC is < 0.2, and kappa lies between 0.9 and 2.0. (E1c) The memoryless walker result (area 0.95, kappa 1.4) is reproduced at g = 0 (code check). Falsified: E1a if all g give exponent >= 0.85 or <= 0.55 (no cube-root-like regime from this memory); E1b is only evaluated if E1a holds. Limit: one board size, 6 seeds per g, 2^26 steps, TSAW at large g can trap itself (reported as stalls).
Clarification (still before any E1 run): the TSAW chooses among all 4 neighbours with weight exp(-g * visits(neighbour)); the "cookie" ew walker is dropped (too little memory to matter) and E1 is the TSAW alone.

### Correction 2026-10-21: board artefacts in the late-highway counts (B5, item 17)
